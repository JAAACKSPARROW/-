# 计算流程与证据

本流程适用于肽序列二分类论文的计算部分。模型、维度、清洗方法、种子和阈值由所复现的论文/代码决定；不是每篇论文都需要 ESM、CleanLab 或六种模型。

## 1. 固定来源与建立实验目录

记录论文 DOI、补充材料来源、作者仓库 commit、数据校验和、Python/依赖版本、设备、线程设置及精度。保留原文、源码、历史输出与本次产生的结果各自的身份。

已有实验先保存只读意义上的快照及逐文件 SHA256；新实验用不同目录。只在明确理解哪些阶段已完成时恢复失败运行；不能把部分运行写成完整运行。

推荐的每次运行产物：`run_plan.json`、`src/`、`results/`、`models/`、`data_audit/`、`logs/`、`executed_notebooks/`、报告。可沿用项目已有命名。

## 2. 审计数据身份

计算样本/类别数、序列长度、缺失值、非法残基、完全重复、序列重复及冲突标签。不要直接改写原始数据来修复这些问题。Excel 尾部格式空行与真实缺失样本分别处理。

清洗后的特征、标签和原序列必须用稳定 ID 对齐并验证；不得仅凭相同行数推断顺序。分别记录原始文件的声明类别和实际标签含义，特别是随机序列负例不等于实验验证无活性。

## 3. 尝试原代码并隔离修复

先保留实际原样执行的错误与失败位置。路径、缺包、API 或形状兼容问题在副本中修复，保存 diff。模型逻辑变化另列实验；不得只把旧 Notebook 的保存输出当作执行成功。

若 Notebook 后半段依赖未公开的筛选输入，可提取可执行的训练段，说明缺失的下游任务。整个执行脚本退出0不意味着所有原始 Notebook 原样成功；分别检查其状态。

## 4. 从序列重算表示

记录 checkpoint、校验和、表示层、tokenizer、BOS/EOS/padding 处理、池化、归一化、batch size、device、dtype、eval/no_grad 和截断规则。确认每条输入对应一个输出。

把预训练表示推理与下游监督训练分开说明。缓存权重可以复用；“完整重跑”仍应重新做前向计算，除非用户明确允许跳过。复用已生成特征时核对源数据哈希、序列顺序及配置，并明确记录缓存命中。

## 5. 对齐作者特征

按样本 ID 比较形状、有限值、dtype、余弦相似度、MAE、RMSE、最大绝对误差。精度和 batch 导致的误差容限应解释，不能为了通过而事后放宽。

分清“两次自有计算一致”和“重算值与作者值一致”：二者检验不同事实。

## 6. 标签清洗

优先复用公开实现；实现缺失时，明确标为独立重建。记录分类器、OOF 概率的 CV 方案、随机种子、清洗软件版本、API、过滤规则与分数定义。

保存每条样本的原标签、预测概率、可疑程度和保留/删除决定。比较保留数量、类别数、交集、仅作者保留、仅重建保留及逐样本决定一致率。不能只对齐最终数量，也不能悄悄把删除样本改成重新标注。

## 7. 训练方案与调参

从原代码提取完整网格、默认参数及实际评分函数；同时检查论文描述。完整记录训练/留出划分的成员、是否分层、CV shuffle 和种子、搜索得分、失败候选及最佳参数。

若论文参数与代码搜索不同，建立两个独立方案：一条按代码完整搜索，一条按论文固定参数重跑。固定参数实验不能再调参追近论文结果。

## 8. 重复训练与评估

采用原公开协议；原种子缺失时记录缺口和新增假设。分别记录划分种子、估计器种子和深度学习初始化。每个划分重新拟合模型，不把上一次 fit 的状态混入下一次。

标准指标通常包括 accuracy、BACC、positive precision/recall、specificity、F1、MCC、ROC-AUC 和 average precision。若列名为 `pr_auc` 而实现是 average precision，要在报告中说明，不能与梯形 PR-AUC 混称。

混淆矩阵顺序为 `[[TN, FP], [FN, TP]]`，正类明确为1或实际对应标签。AUC使用连续得分；SVM decision_function 不是概率。

## 9. 其他模型及深度学习

执行所需模型的原网格和网络，记录预处理、结构、optimizer、epoch、batch size 和停止规则。若 API 兼容修复只改变 target shape，保存原错误和最小 diff，不顺便调整网络。

单次历史成绩与十次均值分开；各模型必须使用清晰可对照的数据/协议。随机森林等未设置 random_state 的模型可能在固定划分下仍变化，不能靠全局 NumPy seed 宣称确定性。

## 10. 模型产物

区分 CV 最佳模型、每次测试的拟合模型和全量 refit 的部署模型。保存每个产物的训练数据身份、参数和特征配置。比较两个模型在同一输入上的类别、连续得分及适用的内部参数；不能将训练集上的诊断当作新的测试成绩。

## 11. 原结果差异与泄漏审计

建立四类对照：论文报告、作者 Notebook 历史输出、原代码当前重跑、独立重建/改进实验。缺少作者权重时只能比较其报告或保存输出，不声称做过原权重预测。

检查：完整数据先清洗/拟合预处理、调参集与后续测试集交叠、同一 estimator 被多次 fit 后拿来评价旧留出集、重复或相似序列跨集，以及标签/来源分组泄漏。相似度算法、分母、阈值和严格/非严格比较号都要记录。

忠实复现时保留原协议并报告风险；修复泄漏时另设实验，先隔离外层测试，所有清洗/调参只在训练内完成，并按任务考虑序列簇分组。用户未要求时，不把复现任务自动扩张为无泄漏重设计。

## 12. 结果组织与流程解释

每步用“输入 → 操作 → 输出 → 检查”解释。静态流程图应显示作者数据分支、独立清洗分支和论文固定参数分支，不能画成同一个实验。图上结果与 CSV 对齐。

报告列明成功、预期原始失败、修复成功、未公开和未执行项目。给出实际误差和边界，不将结果接近论文写成严格复现成功。

## 比较与验证

`scripts/compare_metrics.py` 接收 UTF-8 CSV：

- 唯一键：`experiment,model,seed`，以原字符串严格匹配，缺失键/重复行/不同键集合均报错。
- 默认指标：`accuracy,balanced_accuracy,precision,recall,specificity,f1,mcc,roc_auc,pr_auc`；可用 `--metrics` 显式选取子集。
- 其他列不会自动作为精度指标。默认绝对容差 `1e-12`，相对容差为0，可显式改动但须解释。
- 输出 `paired_metrics.csv`、`metric_summary.csv`、`comparison.json`。汇总按实验、模型和指标统计，两次各自 SD 使用 `ddof=1`；n=1 时 SD 留空。

先确认两个相同名称的 experiment 实际协议一致，不能只依赖名字。工具比较数值，不替代以下检查：

| 对照项 | 检查方式 |
|---|---|
| 数据与源码 | 原作者输入、运行副本及修复 diff 的哈希 |
| 环境 | Python、依赖、设备、精度和线程设置 |
| 特征 | 行 ID、shape、逐元素误差和容差 |
| 清洗 | 样本决定、OOF 概率和保留集合 |
| 划分 | 每个 seed 的训练/测试成员，不能只比较人数 |
| 网格 | 候选集合、评分规则、每个候选得分和最终参数 |
| 模型 | 同一诊断输入上的预测/得分和适用的内部参数 |

缺少任何证据时标明无法核验。对同一数据反复划分有相关性；不把每个 seed 当作独立外部数据集，不默认做独立样本显著性检验。
